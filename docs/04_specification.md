## 1. システム概要

タレント事務所向けに、次の 2 つを 1 つのアプリで提供する。

| 役割 | 内容 |
|---|---|
| **実績管理システム** | タレントの出演歴（実績）を削除せず全件ストックするデータベース。Web からの新規実績の自動収集（AI）に対応 |
| **プロフィール作成ツール** | ストックから営業先に合わせて実績を選抜（AI 提案）し、自由レイアウトの A4 宣材プロフィールを PDF 出力 |

**基本思想**: データ（実績・写真）とデザイン（テンプレート）を分離する。実績は「貯めるだけ」、プロフィールは「選んで出すだけ」。AI は提案までを担い、確定は必ず人が行う。

## 2. システム構成

### 2.1 アーキテクチャ

```
 利用者PC (Windows / Mac)
 ┌────────────────────────────────────────────┐
 │ ブラウザ (Chrome / Edge / Safari)                              │
 │  ├ SPA (React 18 + TypeScript, Vite ビルド)                    │
 │  │   ├ タレント管理 / 写真管理 / 実績管理                        │
 │  │   ├ レイアウトエディタ（A4実寸キャンバス）                     │
 │  │   └ プレビュー / PDF出力（ブラウザ印刷）                      │
 │  ├ IndexedDB（全データのローカル保存）                           │
 │  └ localStorage（Anthropic APIキーのみ）                        │
 └───────────────┬────────────────────────────┘
                  │ HTTPS（AI機能利用時のみ）
        Anthropic Claude API（モデル: claude-opus-5）
         ├ 営業先別の実績選抜・並べ替え提案
         └ Web検索/ページ取得による出演情報収集（サーバーサイドツール）
```

- サーバーを持たない。AI 機能を使わない限り、完全オフラインで動作する
- ストレージ層は `StorageAdapter` インターフェースに抽象化されており、将来 Google Drive / OneDrive アダプタを追加してもUI・データ形式は変更不要（要件 v0.4 の方針を踏襲）

### 2.2 技術スタック

| 区分 | 採用技術 |
|---|---|
| フロントエンド | React 18 / TypeScript / Vite |
| ローカルDB | IndexedDB（`idb`） |
| バックアップ | JSZip（ZIP書き出し・読み込み） |
| AI | `@anthropic-ai/sdk`（ブラウザ直接呼び出し）。モデル構成は提供側で管理（ユーザーは選択不可）: 選抜 `claude-haiku-4-5`／収集 `claude-sonnet-5`。構造化出力＋サーバーサイド `web_search` / `web_fetch` |
| PDF生成 | HTML/CSS（mm単位の絶対配置）→ ブラウザ印刷で PDF 保存（`@page A4 / margin 0`） |

### 2.3 動作環境

- OS: Windows / macOS（ブラウザ動作のため OS 非依存）
- ブラウザ: Chrome / Edge / Safari 最新版
- 起動: `npm install && npm run dev`（開発）／ `npm run build` で静的サイト化し任意のホスティングに配置可（データは各利用者のブラウザ内に保存される）
- **Mac配布パッケージ**: `起動.command` のダブルクリックで内蔵ランチャー（Go製・Apple Silicon/Intel両対応）がローカルサーバー(127.0.0.1:8787)を起動し、ブラウザを自動で開く。Node.js等のインストール不要。初回のみ右クリック→「開く」（コード署名は提供側の保守項目・未対応）

## 3. 画面構成

| 画面 | URL(ハッシュ) | 概要 |
|---|---|---|
| タレント一覧 | `#/` | 顔写真グリッド。名前・ふりがな・タグの検索。タレント追加 |
| タレント編集 | `#/talent/:id` | タブ構成: 基本情報／写真／経歴（実績）／自己紹介・動画 |
| レイアウトエディタ | `#/editor` | A4 キャンバスでテンプレートを自由編集 |
| プレビュー / PDF | `#/preview/:id` | 実寸プレビュー、テンプレート切替、「PDFに保存/印刷」 |
| 個別レイアウト調整 | `#/layout/:id` | タレント専用のレイアウト編集（テンプレート反映・リセット可） |
| 設定 | `#/settings` | 事務所情報・ロゴ／AI設定（APIキー）／バックアップ |

共通動作: 編集は「保存する」ボタンで確定（未保存はボタン表示で判別）。初回起動時は練習用サンプルタレント 1 名を自動投入。

## 4. 機能仕様

### 4.1 タレント管理

- 登録・編集・削除（削除は写真含め完全削除。確認ダイアログあり）
- 項目: 芸名／ふりがな／ローマ字／性別／生年月日（年齢自動計算・表示切替）／出身地／血液型／身長・体重・B・W・H・足サイズ・頭囲・服サイズ／趣味・特技（複数）／タグ（複数）／自己紹介文／動画リンク（ラベル＋URL、複数）／情報源URL（複数）
- 一覧はふりがな順ソート。検索は部分一致
- **AIインポート**: 既存のWord/Excelプロフィール文面を貼り付けると、AIが基本情報＋経歴に構造化。内容を確認してからタレントとして登録（移行の主経路）

### 4.2 写真管理

- ドラッグ&ドロップまたはファイル選択で複数登録（画像形式）
- 用途タグ: バストアップ／全身／スナップ1〜3（**最大5枠**）。用途ごとに「採用」写真を 1 枚選択し、テンプレートの対応枠に表示。枠自体はエディタで自由に追加・削除・サイズ変更できる
- 枠内調整: 横位置・縦位置・拡大率のスライダー（object-position / scale）
- 実体はブラウザ内（IndexedDB の Blob）に保存

### 4.3 実績（経歴）管理 — ストック方式

- 実績は**削除せず全件ストック**。行ごとの「表示」チェックでプロフィール掲載を切り替え（非表示行はグレー表示で保持）
- 項目: カテゴリ（映画/TV/CM/MV/舞台/その他）／年／作品名／話数・部門／役名／監督・局／補足／強調フラグ／表示フラグ／情報源URL
- 「強調」は赤字太字で出力（最新作・主要実績向け）。行の並べ替え（↑↓）可
- 出力時はカテゴリ別にグループ化し、カテゴリごとの慣行に沿って整形（例: 映画は「年『作品』監督：◯◯ 役名」、TVは「年 局『作品』話数 役名」）

### 4.4 AI機能

前提: 設定画面で Anthropic APIキーを登録（localStorage 保存。バックアップ ZIP には含めない）。AI はすべて**提案のみ**で、反映→保存の二段階を人が操作する。実績の文面を AI が書き換えることはない。

**モデル構成（提供側管理）**: 利用モデルはユーザーに公開せず、提供側の保守作業として構成を管理する（コード内 `AI_CONFIG` の変更＋デプロイ）。現行構成: 選抜・並べ替え(a)＝`claude-haiku-4-5`（結果は人がプレビュー確認できるため軽量で運用）／Web収集(b)＝`claude-sonnet-5`（同姓同名判別・確度判定の判断力と最新検索ツール対応が必要なため）。モデル改廃・コスト最適化は月額保守の範囲で提供側が実施する。

#### (a) 営業先別の選抜・並べ替え提案

- 入力: 営業先・用途の自由文（例: 「飲料メーカーB社のCM案件向け。競合他社のCM実績は非表示に」）
- 出力: 全実績の並び順＋表示/非表示＋強調（1〜3件）の提案と、方針説明（reason）
- **競合バッティング回避**: 営業先から競合関係（他球団・同業他社・他ブランド等）を推測し、該当実績を非表示提案。競合理由は説明文に明記
- 安全策: 応答はJSONスキーマで構造化。実在IDのみ受理・全件網羅を検証（欠落は現状維持で補完）。プレビューで確認後に反映

#### (b) Webからの出演情報収集（実績DB化）

- 情報源: タレントに登録した URL（事務所HPのお知らせ、X 等）＋ Web検索。サーバーサイドツール（`web_fetch` / `web_search`、各最大8回）で調査
- 出力: 新規実績の候補リスト（カテゴリ/年/作品名/役名/局・監督/補足/**情報源URL**/**確度: 高・中・低**）と調査要約
- 品質担保: 登録済み実績を渡して同姓同名を判別・重複を除外（AI側＋アプリ側の二重）。未確定情報・噂は除外指示。確度「低」は初期チェックOFF
- 取り込み: チェックした候補のみ「表示で追加」または「非表示（ストックのみ）で追加」
- 制約: X は外部取得が制限されるため Web 検索経由で取得できる範囲。処理は約1分。長い調査は `pause_turn` 継続（最大5回）で対応

#### (c) エラー処理

APIキー未設定/不正・利用制限・通信断・AI応答不正はそれぞれ日本語メッセージで通知。安全分類による拒否（refusal）はフォールバック（`fallbacks: "default"`）を設定した上で、最終的に拒否された場合は案内を表示。

### 4.5 レイアウトエディタ

- A4縦（210×297mm）実寸キャンバス。ズーム 60/85/100/140%
- 要素種別: テキスト（データ項目バインド or 固定文言）／写真枠（用途指定）／経歴リスト（カテゴリ複数指定・強調色）／罫線／動画リンク枠／事務所フッター
- テキストのバインド項目: 氏名＋ローマ字／氏名／ふりがな／ローマ字／生年月日(年齢)性別／身長・体重／サイズ行／趣味・特技／自己紹介／出身地
- 操作: ドラッグ移動・8方向リサイズ（0.5mmスナップ）／**ページ中央への吸着ガイド（PowerPointのスマートガイド風）**／矢印キー微調整（Shiftで5mm）／Delete削除／前面・背面切替／プロパティパネルで座標(mm)・サイズ(pt)・太字・色・揃えを指定
- フォント: **ゴシック／明朝／丸ゴシック／欧文セリフ／欧文スクリプトの5種**から要素ごとに選択（Mac/Windows標準搭載フォントで構成）
- **標準テンプレート3種を同梱**: 写真1枚／写真2枚（実物サンプル再現）／写真3枚。タレントごとにプレビュー画面で切替
- **タレント個別レイアウト**: テンプレートのコピーをタレント専用に調整可能（`#/layout/:id`）。任意のテンプレートを反映し直したり、「テンプレートに戻す」で個別調整を破棄できる。テンプレート自体も「標準に戻す」で初期配置にリセット可
- **マグネット吸着**: ドラッグ中、他要素の左端・上端およびページ中央に吸着（ガイド線表示）。見出しと内容枠の左揃えが直感操作で可能
- エディタ・プレビュー・PDF は同一の描画コンポーネントを共有（WYSIWYG保証）

### 4.6 プレビュー・PDF出力

- 実寸プレビュー → 「PDFに保存/印刷」でブラウザ印刷ダイアログ（余白なし推奨）
- 動画リンク・メール・URL は PDF 上でクリック可能
- 写真未設定枠は編集画面ではプレースホルダ表示、印刷時は非表示

### 4.7 事務所設定（ブランド共通）

- 事務所名・電話・住所・メール・WebサイトURL・ロゴ画像を登録
- フッター要素として全タレントのプロフィール下部に自動配置。1か所の変更で全員に反映

### 4.8 バックアップ

- ZIP書き出し: 全データ（タレント・実績・写真・テンプレート・事務所情報）を `data.json`＋`blobs/` 形式で保存（ファイル名 `profile-backup-YYYYMMDD.zip`）
- 読み込み: 同形式のZIPを復元（同一IDは上書き）。PC移行・世代保管に使用
- APIキーはバックアップに**含めない**（秘匿情報のため）

## 6. セキュリティ・プライバシー

- 全データはローカル（利用者PCのブラウザ内）。外部サーバーへの保存なし
- AI 利用時に送信されるのは処理に必要なテキストのみ（選抜: 実績一覧・自己紹介・営業先文／収集: 氏名・登録実績・情報源URL）。**写真・連絡先・サイズ等の個人情報は送信しない**
- APIキーは localStorage のみに保存し、バックアップ対象外
- タレント削除時は写真 Blob 含め完全削除

## 7. 性能・制約値（目安）

| 項目 | 値 |
|---|---|
| 想定規模 | タレント 50〜500名、写真 数千枚 |
| AI選抜 | 数十秒（経歴50件規模） |
| Web収集 | 約1分（検索・取得 各最大8回） |

## 8. 既知の制約と今後（要件 v0.4 との差分）

| 項目 | v1 実装 | 今後（ロードマップ参照） |

| データ保存 | ローカル（同一PC・同一ブラウザ）。共有はバックアップZIPの受け渡し | Google Workspace 共有ドライブ（StorageAdapter追加）→ 複数人同時利用・版チェック。さらに OneDrive |

| 出力 | PDF（単体）。一括出力UIなし | 一括PDF・pptx/画像出力 |
| AI | 選抜提案・Web収集 | 文章整形・既存資料の一括構造化取り込み・定期巡回通知 |
| 更新履歴 | updated_at のみ | 監査ログ・出力履歴 |

## 9. 導入・運用手順（v1）

1. `npm install && npm run dev` で起動（または `npm run build` → 静的ホスティング）
2. 設定画面: 事務所情報・ロゴを登録／（AI利用時）APIキーを登録
3. タレントを登録し、写真・実績を入力（実績はWeb収集の活用可）
4. 営業時: AI選抜 → 確認・反映 → 保存 → プレビュー → PDF
5. 週1回程度バックアップZIPを書き出し、Googleドライブ等に保管
