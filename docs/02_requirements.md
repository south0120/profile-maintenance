## 1. 背景と需要分析

### 1.1 現状の課題(As-Is)

タレント事務所では、所属タレントの宣材プロフィールを Word / PowerPoint で 1 人ずつ手作業で作成している。

| # | 課題 | 影響 |
|---|---|---|
| C1 | 新規作成に時間がかかる（レイアウト調整・写真配置・体裁合わせ） | 1 人あたり数時間の作業。タレント増員時にスケールしない |
| C2 | 写真差し替え・サイズや経歴の更新のたびにレイアウトが崩れる | 更新が後回しになり、古い情報のまま送付されるリスク |
| C3 | 事務所ロゴ・連絡先などの共通要素がファイルごとにバラバラ | ブランドの統一感がない。連絡先変更時に全ファイル修正が必要 |
| C4 | ファイルが分散し、どれが最新版か分からない | 版管理ミス、誤送付、担当者不在時に更新できない属人化 |
| C5 | 用途別に別ファイルを複製している | 複製の数だけ更新漏れが発生 |

### 1.2 利用形態・規模（確定事項）

| 項目 | 内容 |
|---|---|
| 対応 OS | **Windows / Mac 両対応**（ブラウザで動作するため OS 非依存） |
| UI | ブラウザ（Chrome / Edge / Safari 最新版） |
| データ保存先 | **Google ドライブ**。事務所は **Google Workspace 契約**のため、**共有ドライブ（Shared Drive）** に専用フォルダを作成して保持（個人依存がなく退職時の引き継ぎも安全）。**将来は OneDrive への対応も想定**（§5.3 ストレージ抽象化） |
| 利用者数 | **複数人（マネージャー・デスク数名）が各自のブラウザから同じデータを操作** |
| 規模 | 所属タレント **50〜500 名**、写真はタレントあたり 5〜20 枚（最大 1 万枚規模） |
| テンプレート | 当面は**営業用 1 種**（実物サンプル様式を再現） |

**期待効果**: タレント 100 名 × 年 4 回更新 × 1 回 2 時間（手作業）＝ 年 800 時間 → フォーム入力 15 分に短縮できれば**年 700 時間規模の削減**。複数人が同じ最新データを見るため、誤送付・版管理ミスも解消。

### 1.3 ゴール(To-Be)

> タレント情報を Google ドライブ上で一元管理し、スタッフ全員が**ブラウザから「入力・写真アップロード → プレビュー → PDF 出力」の 3 ステップ**で、事務所ブランドの統一されたプロフィールを出力できる。レイアウトはブラウザ上のエディタで**ドラッグ操作により自由に配置変更**でき、変更は全タレントに一括反映される。

## 2. プロフィール資料の要件（出力物の仕様）

実物サンプル（営業用・A4 縦 1 枚）を基準とする。
参考: [俳優の「プロフィール資料」何が必要？（俳優の下積み生活）](https://manami-hayashi.com/blog/actor-portfolio/)

### 2.1 サンプルから抽出したレイアウト構成

```
┌─────────────────────────────────────┐
│  氏名（大・明朝系） ローマ字表記                      │ ← ヘッダー
│  ──────────────────────────────     │
│  生年月日（年齢自動計算）（性別）                     │
│  身長・体重                                          │ ← 基本情報ブロック
│  B/W/H・足サイズ・頭囲・服サイズ                      │   （中央揃え・複数行）
│  趣味・特技（カンマ区切りリスト）                      │
│                                                     │
│  ┌──────────┐   ┌──────────┐                       │
│  │ バストアップ │   │  全身写真  │                    │ ← 写真ブロック×2
│  └──────────┘   └──────────┘                       │
│                                                     │
│ 【最新の活動状況】                                    │
│ 【映画】               【TV】                        │
│  ・強調行(赤字太字)      ・年 局『作品名』話数 役名     │ ← 経歴ブロック
│  ・年『作品名』監督 役名  【CM】                       │   （2カラム・
│  ・…                   ・…                          │    カテゴリ別リスト）
│                        【MV】                        │
│ 【自己紹介】            ・…                          │
│  自由文テキスト         ┌────────────────┐           │
│                        │【動画資料】URLリンク │        │ ← リンク枠
│                        └────────────────┘           │
│  ─────────────────────────────────                  │
│  [ロゴ/マーク] 会社名  ☎電話   住所 / ✉メール / 🌐URL  │ ← フッター(共通)
└─────────────────────────────────────┘
```

### 2.2 記載項目（データ項目）

- **ヘッダー**: 芸名（漢字）、ふりがな（任意）、ローマ字
- **基本情報**: 生年月日→年齢自動計算（表示/非表示可）、性別、身長、体重、B/W/H、足サイズ、頭囲、服サイズ（例: L/XL）、血液型（任意）、出身地（任意）
- **趣味・特技**: 複数項目（カンマ区切り表示）
- **写真**: バストアップ＋全身の 2 枚が基本。差し替え候補を複数登録し選択
- **経歴（最新の活動状況）**: カテゴリ（映画/TV/CM/MV/舞台/その他）別の明細リスト
  - 明細行: 年、作品名、話数・部門、役名、監督/局名、補足（映画祭入選等）
  - **強調表示フラグ**（サンプルの赤字太字のように最新作・主要作を目立たせる）
- **自己紹介**: 自由文（改行可）
- **動画資料**: ラベル＋URL の複数リンク（PDF 上でクリック可能なリンクとして出力）
- **事務所要素（全タレント共通・フッター）**: **会社ロゴ・マーク画像をページ下部に配置**し、会社名、電話、住所、メール、Web サイト URL を併記（実物サンプルのフッターと同構成）

### 2.3 形式

- A4 縦・1 枚（情報量に応じて 2 枚まで対応）
- PDF 出力（リンク埋め込み・日本語フォント埋め込み）。印刷にも耐える解像度
- 明朝系（氏名）＋ゴシック系（本文）の混植など、フォント指定が可能であること

## 3. 機能要件

優先度: **[M] MVP 必須 / [S] 第2フェーズ / [C] 将来検討**

### F1. タレント情報管理
- [M] タレントの登録・編集・削除（ゴミ箱方式）・一覧・検索（名前・ふりがな・タグ）
- [M] §2.2 の全項目を構造化フィールドで保持。経歴はカテゴリ別の明細行（並べ替え可・強調フラグ付き）
- [M] 年齢は生年月日から自動計算（出力時に表示/非表示を選択可）
- [M] 500 名規模でも一覧・検索が快適に動作（顔写真サムネイル付きグリッド/リスト表示）
- [S] タグ・カテゴリ管理（俳優/モデル/声優、性別、年代等）による絞り込み
- [S] **初期データ移行**: 既存の名簿（Excel 等）は存在しないため、既存の Word / PowerPoint プロフィール資料の文面を貼り付けて AI が明細に構造化する取り込み（F8）を移行の主経路とする
- [C] CSV / Excel からの一括インポート（将来、他システムからの移行が発生した場合用）
- [C] タレント本人による下書き入力 → 事務所承認フロー

### F2. 写真管理
- [M] タレントごとに複数写真を登録（JPEG/PNG/HEIC、ドラッグ&ドロップ対応）。実体は Google ドライブに保存
- [M] 写真に用途タグ（バストアップ/全身/スナップ）を付与し、テンプレートの写真枠へ選択配置
- [M] 写真枠内でのトリミング・位置調整（枠に自動フィット＋手動微調整）
- [M] サムネイル自動生成（500 名×多数枚でも一覧が軽快）
- [S] 撮影日管理・古い写真の入替アラート
- [C] 背景切り抜き・明るさ自動補正

### F3. レイアウトエディタ（本ツールの中核）
- [M] **ブラウザ上の WYSIWYG エディタで、要素を自由にドラッグ移動・リサイズできる**
  - 要素の種類: テキスト（データ項目バインド／固定文言）、写真枠、経歴リスト枠（カテゴリ指定）、画像（ロゴ・マーク）、リンク枠、罫線・図形、フッター
  - スナップガイド・グリッド・整列（左揃え/中央/等間隔）・重なり順(z-order)
  - フォント・サイズ・太字・色・行間・揃えの指定（強調行のスタイル指定を含む）
  - A4 縦キャンバス上で実寸プレビューしながら編集（ズーム可）
- [M] レイアウトは**テンプレート**として保存し、全タレントに適用（データとレイアウトの分離）
- [M] MVP では**営業用テンプレート 1 種**（実物サンプル様式を再現）を同梱し、これをエディタでカスタマイズして使う
- [M] テンプレート修正（ロゴ変更・枠移動等）は、全タレントの次回出力に即時反映
- [S] テンプレート複数管理（オーディション用等の追加）・複製・項目の表示/非表示切替
- [S] タレント個別のレイアウト微調整（テンプレートからのオーバーライド。経歴が多い人だけ枠を広げる等）
- [S] リストのあふれ制御（枠に入り切らない場合の警告／自動フォントサイズ縮小／2 ページ目送り）
- [C] 複数ページテンプレート・ページマスター

### F4. ブランド管理（事務所共通アセット）
- [M] 会社ロゴ・マーク画像、会社名・電話・住所・メール・URL、ブランドカラー、使用フォントを一元登録
- [M] テンプレートの**ページ下部（フッター）にロゴ・マークを自動配置**。変更は 1 箇所の修正で全タレントに反映

### F5. 出力・共有
- [M] PDF 出力（A4・300dpi 相当、フォント埋め込み、動画資料 URL はクリック可能リンク）
- [M] 出力前プレビュー（エディタと同一描画で見た目が一致）
- [M] 一括出力（一覧で複数タレントを選択 → 各 1 PDF を Google ドライブの出力フォルダまたはローカルへ書き出し）
- [S] 画像（PNG/JPEG）出力、PowerPoint（.pptx）出力（既存業務フローとの互換用）
- [C] 共有用の静的 HTML 書き出し（事務所サイト掲載用）

### F6. データ保全・版管理
- [M] 全データ（タレント情報・写真・テンプレート・アセット）を **Google ドライブの専用共有フォルダ**に保存
- [M] Drive の共有設定＝アクセス権管理（フォルダを共有されたスタッフだけが利用可能）
- [M] 更新履歴の記録（いつ・誰が・どのタレントの何を変更したか。Google アカウント名で記録）
- [M] Google ドライブの版管理（ファイルの版履歴）で誤更新から復元可能。加えてワンクリックで ZIP バックアップを書き出し
- [S] 出力履歴と旧版 PDF の保管、更新リマインド（例: 経歴が 6 か月更新されていない）

### F7. マルチユーザー・アクセス管理
- [M] **Google アカウントでログイン**（OAuth）。Drive フォルダへのアクセス権がそのまま利用権限になる
- [M] **複数人の同時利用**を想定した競合制御:
  - タレント 1 名＝1 データファイル単位で保存し、同時編集の衝突範囲を最小化
  - 保存時に版チェック（他者が先に更新していた場合は警告し、上書き前に差分を提示）
  - 編集開始時に「◯◯さんが編集中」の表示（ソフトロック）
- [S] 操作ログの一覧画面、閲覧専用モード
- [C] 役割分担（管理者のみテンプレート編集可、など）

### F8. AI 支援機能（業務効率化）

> 方針: AI はあくまで**下書き・候補の提案役**とし、保存はすべて人の確認を経る（宣材は対外資料であり、誤情報の混入を防ぐため）。

- [S] **文章の整形・校正**: 自己紹介文・PR 文を AI が校正（誤字脱字、トーン統一、指定文字数への要約・膨らませ）。修正案を並べて提示し、担当者が採用/編集して保存
- [S] **経歴入力の自動構造化**: 既存の Word/PowerPoint プロフィールや箇条書きテキストを貼り付けると、AI が「年・カテゴリ・作品名・役名・監督/局」の明細行に自動変換 → 確認して取り込み（**既存データからの移行作業を大幅短縮**）
- [S] **表記ゆれの正規化**: 経歴の書式（『』の付け方、年表記、カテゴリ分類）を事務所ルールに揃える提案
- [S] **Web からの最新活動情報の収集**: タレント名＋既知の出演作で Web 検索し、未登録の出演情報・公開日決定などの候補を提示 → 担当者が真偽を確認して経歴に追加（同姓同名・誤情報リスクがあるため**自動反映はしない**。情報源 URL を併記）
- [C] 定期巡回による新着情報の通知、写真選定の補助（用途タグの自動判定）

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 動作環境 | Windows / Mac。Chrome / Edge / Safari 最新版。**インストール不要**（URL を開くだけで利用開始） |
| 性能 | タレント 500 名・写真 1 万枚規模で、一覧表示・検索 1 秒以内（ブラウザ内キャッシュ・インデックス利用）、エディタ操作 60fps 目安、PDF 1 件 10 秒以内 |
| データ保護 | データは事務所の Google ドライブ内に保持（外部 DB を持たない）。アクセスは Google アカウント認証＋Drive 共有権限で制御。アプリは Drive の**専用フォルダのみ**にアクセス（drive.file スコープ）し、他のファイルには触れない |
| 個人情報保護 | タレント削除時は写真含め完全削除（ゴミ箱経由）。共有フォルダの共有範囲は事務所ドメイン/指定メンバーに限定する運用を前提 |
| 信頼性 | 編集内容の自動保存。ネットワーク断時は編集を一時保持し再接続時に保存（保存失敗を明示） |
| 操作性 | IT に詳しくない担当者が研修なしで使える日本語 UI。エディタは PowerPoint 操作感に寄せる |
| 保守性 | データ（JSON）とレイアウト（テンプレート JSON）を分離。項目追加・テンプレート追加が容易な構造 |
| コスト | Google ドライブは既存契約を利用。アプリ本体は静的ホスティング（無料〜数百円/月）で運用可能。専用サーバー・DB 費用なし。AI 機能のみ従量課金（利用頻度により月数百〜数千円目安） |
| AI 利用時の扱い | AI へ送信するのは処理対象のテキストのみ（写真・連絡先等は送らない）。AI の提案は必ず人の確認を経て保存。Web 収集情報は情報源 URL 付きで提示し自動反映しない |

## 5. アーキテクチャ（案）

### 5.1 方式比較（「Google ドライブのデータを複数人がブラウザで操作」の実現方法）

| 方式 | 概要 | 評価 |
|---|---|---|
| **A. ブラウザ SPA ＋ Google Drive API（サーバーレス）** | アプリは静的サイトとして配信。ブラウザから Google Drive API で直接データを読み書き。認証は Google OAuth | **◎ 推奨**。インストール不要・Win/Mac 対応・複数人利用・サーバー費用ほぼゼロ。データは文字通り「Google ドライブの中」 |
| B. ローカルアプリ＋Google Drive for Desktop 同期 | v0.2 案のローカルアプリを各 PC に入れ、データフォルダを Drive 同期フォルダに置く | △ **同時編集で DB ファイル（SQLite）が同期競合し破損リスク**。複数人前提では非推奨 |
| C. 小規模クラウドサーバー（SaaS 型） | サーバー＋DB を立て、写真のみ Drive 連携 | ○ 競合制御は最も堅牢だが、サーバー運用・月額費用・個人情報の外部保管が発生。将来 A で限界が出た場合の移行先 |

**結論**: **A（ブラウザ SPA ＋ Drive API）を採用**。「1 タレント＝1 ファイル」の設計と版チェックで同時編集の競合を実用上問題ないレベルに抑える（§F7）。

### 5.2 構成図

```
 スタッフ各自の PC (Win/Mac) ── ブラウザだけで利用
 ┌──────────────────────────────┐
 │ ブラウザ (Chrome/Edge/Safari)                    │
 │  ├ タレント管理画面 (React SPA)                   │
 │  ├ レイアウトエディタ (A4キャンバス編集)            │
 │  ├ プレビュー & PDF生成 (エディタと同一のHTML/CSS   │
 │  │   描画 → ブラウザ印刷 or クライアントPDF生成)    │
 │  └ ローカルキャッシュ (IndexedDB: 一覧・検索用      │
 │      インデックス、サムネイル)                     │
 └──────────────┬───────────────┘
                 │ Google OAuth ＋ Drive API (HTTPS)
 ┌──────────────┴───────────────┐
 │ Google ドライブ（事務所の共有フォルダ）             │
 │  ├ talents/<id>/profile.json … タレントデータ     │
 │  ├ talents/<id>/photos/      … 写真原本          │
 │  ├ templates/eigyo.json      … 営業用テンプレート │
 │  ├ assets/                   … ロゴ・マーク・フォント│
 │  ├ index.json                … 一覧用インデックス  │
 │  └ exports/                  … 一括出力したPDF     │
 └──────────────────────────────┘
   ※アプリ本体(HTML/JS)は静的ホスティング(Vercel等)から配信
```

- **エディタ・プレビュー・PDF が同一の HTML/CSS 描画**を共有し「見たまま出力」（WYSIWYG）を保証
- 「1 タレント＝1 JSON ファイル」により、別々のタレントを複数人が同時編集しても衝突しない。同一タレントの同時編集は版チェック＋編集中表示で保護
- `index.json`（氏名・タグ・サムネイル参照の一覧）と IndexedDB キャッシュで、500 名規模でも一覧・検索を 1 秒以内に

### 5.3 技術スタック（推奨）

| レイヤ | 推奨 | 理由 |
|---|---|---|
| UI | React + TypeScript + Vite | エディタのような対話的 UI に実績豊富 |
| レイアウトエディタ | 自作キャンバス（DOM/CSS transform ベース）＋ dnd 系ライブラリ | PDF 描画と同一の DOM を編集対象にでき、WYSIWYG を担保 |
| データアクセス | Google Drive API v3（drive.file スコープ）＋ Google Identity Services (OAuth) | サーバーレスで Drive 直接読み書き。専用フォルダのみアクセスで安全。**Workspace のためログインを事務所ドメインに限定可能** |
| ストレージ抽象化 | アプリ内のデータアクセスを **StorageAdapter インターフェース**（list/read/write/版チェック）に集約し、MVP は GoogleDriveAdapter を実装 | **将来の OneDrive 対応**は MicrosoftGraphAdapter の追加のみで実現でき、画面・エディタ・データ形式（JSON）は無改修で流用できる |
| ローカルキャッシュ | IndexedDB（idb） | 一覧・検索の高速化、オフライン閲覧 |
| 画像処理 | ブラウザ内 Canvas（リサイズ・サムネイル・HEIC は heic2any） | サーバー不要で完結 |
| PDF 生成 | HTML/CSS → ブラウザ印刷（CSS @page）／一括出力は クライアントサイド PDF 生成 | リンク・日本語フォント埋め込み対応。サーバー不要 |
| .pptx 出力（S） | pptxgenjs（クライアントサイド） | 既存 PowerPoint フローとの互換 |
| AI 支援（S） | Claude API（文章整形・構造化）＋ Web 検索ツール（最新活動情報の収集） | 高品質な日本語処理。API キー保護のため Vercel 上の軽量サーバーレス関数経由で呼び出す（データは保存しない中継のみ） |
| ホスティング | Vercel / Cloudflare Pages 等の静的配信（AI 中継関数も同居） | 無料〜低コスト。アプリにデータは置かない |

**導入時に必要な準備（初回のみ・開発側で実施可能）**: Google Cloud プロジェクトの作成と OAuth クライアント設定（無料）。利用者は Google アカウントで事務所の共有フォルダに参加するだけ。

## 6. データモデル（案）

Google ドライブ上のファイル構成（DB サーバーは持たない）:

```
（共有フォルダ）profile-maintenance/
 ├─ agency.json          … 事務所情報: 会社名, tel, 住所, email, website,
 │                          ロゴ・マーク画像参照, brand_color, fonts
 ├─ index.json           … タレント一覧インデックス（id, 氏名, かな, タグ,
 │                          サムネイル参照, updated_at, updated_by）
 ├─ talents/<id>/
 │   ├─ profile.json     … stage_name, kana, romaji, gender, birthdate,
 │   │                      height, weight, bust, waist, hip, shoe_size,
 │   │                      head_size, clothing_size, blood_type, birthplace,
 │   │                      hobbies_skills[], self_intro, status, tags[],
 │   │                      careers[]（category, year, title, episode,
 │   │                        role_name, director_or_station, note,
 │   │                        is_highlight, sort_order）,
 │   │                      video_links[]（label, url）,
 │   │                      photo_assign（枠→写真の割当・crop情報）,
 │   │                      rev, updated_at, updated_by
 │   └─ photos/          … 写真原本＋サムネイル
 ├─ templates/eigyo.json … 営業用テンプレート（layout_def）
 ├─ assets/              … ロゴ・マーク画像、フォント
 ├─ logs/audit-YYYYMM.jsonl … 更新履歴
 └─ exports/             … 一括出力 PDF
```

- `profile.json` の `rev`（版番号）で楽観ロック: 保存時に Drive 上の版と照合し、他者更新があれば警告
- Google ドライブ自体のファイル版履歴が二重のセーフティネットになる

## 7. 画面構成（案）

1. **ログイン**: 「Google でログイン」ボタンのみ（初回は共有フォルダの選択/作成）

## 9. 確定事項と未確定事項

### 確定（ヒアリング済み）

1. 規模: 所属タレント 50〜500 名
2. 出力様式: 実物サンプル（営業用・A4 縦 1 枚）を標準テンプレートとして再現
3. OS: Windows / Mac 両対応（ブラウザ利用）
4. データ: Google ドライブに保存し、複数人がブラウザから操作
5. テンプレート: 当面は営業用 1 種
6. サイン: 会社ロゴ・マークをページ下部（フッター）に配置する意味
7. アカウント: **Google Workspace 契約**。データは共有ドライブに配置し、ログインは事務所ドメインに限定
8. ストレージ: MVP は Google ベース。**将来 OneDrive も想定**（ストレージ抽象化で対応、Phase 3）
9. 既存名簿データ: **なし**。初期移行は既存 Word/PPT 資料からの AI 構造化取り込み（F8）で行う

1. 同時利用の人数規模（2〜3 名か、10 名以上か）
2. 印刷会社入稿の有無（トンボ・CMYK 対応が必要か）
3. 共有ドライブの管理者（Google Cloud の OAuth 設定・共有ドライブ作成を行う Workspace 管理者アカウント）
