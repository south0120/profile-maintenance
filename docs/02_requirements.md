# 需要分析・システム要件定義書

タレントプロフィール作成・メンテナンスツール
作成日: 2026-07-30 ／ 版: **v0.2**（依頼者フィードバック反映版）

> v0.1 → v0.2 の主な変更
> - 実物サンプル（株式会社リアルメーカーズ様式の宣材 1 枚もの）を出力仕様の基準に採用
> - **レイアウトを自由に動かせるエディタ**を中核機能に昇格（v0.1 では将来検討だった）
> - 動作形態を「クラウド SaaS」から「**ローカル PC 上で動作し、画面はブラウザ**」に変更。データはローカル保存
> - 規模想定を **所属タレント 50〜500 名** に更新

---

## 1. 背景と需要分析

### 1.1 現状の課題(As-Is)

タレント事務所では、所属タレントの宣材プロフィールを Word / PowerPoint で 1 人ずつ手作業で作成している。

| # | 課題 | 影響 |
|---|---|---|
| C1 | 新規作成に時間がかかる（レイアウト調整・写真配置・体裁合わせ） | 1 人あたり数時間の作業。タレント増員時にスケールしない |
| C2 | 写真差し替え・サイズや経歴の更新のたびにレイアウトが崩れる | 更新が後回しになり、古い情報のまま送付されるリスク |
| C3 | 事務所ロゴ・サイン・連絡先などの共通要素がファイルごとにバラバラ | ブランドの統一感がない。連絡先変更時に全ファイル修正が必要 |
| C4 | ファイルが分散し、どれが最新版か分からない | 版管理ミス、誤送付、担当者不在時に更新できない属人化 |
| C5 | 用途別に別ファイルを複製している | 複製の数だけ更新漏れが発生 |

### 1.2 利用形態・規模（確定事項）

| 項目 | 内容 |
|---|---|
| 動作環境 | **ローカル PC 上で動作。UI はブラウザ**（Chrome/Edge 等）で操作 |
| データ保存先 | **ローカル**（PC 内のデータフォルダ。DB ファイル＋写真フォルダ）。クラウド不要 |
| 規模 | 所属タレント **50〜500 名**、写真はタレントあたり 5〜20 枚（最大 1 万枚規模）を想定 |
| 利用者 | 事務所スタッフ（マネージャー・デスク）。当面は 1 台の PC での利用を想定し、将来的に LAN 内共有を検討 |

**期待効果**: タレント 100 名 × 年 4 回更新 × 1 回 2 時間（手作業）＝ 年 800 時間 → フォーム入力 15 分に短縮できれば**年 700 時間規模の削減**。加えて誤送付・ブランド不統一という品質リスクの解消。

### 1.3 ゴール(To-Be)

> タレント情報をローカルで一元管理し、**「入力・写真アップロード → テンプレート選択 → PDF 出力」の 3 ステップ**で、事務所ブランドの統一されたプロフィールを出力できる。レイアウトはブラウザ上のエディタで**ドラッグ操作により自由に配置変更**でき、変更はデータを保ったまま全タレントに適用できる。

## 2. プロフィール資料の要件（出力物の仕様）

実物サンプル（リアルメーカーズ様式・A4 縦 1 枚）を基準とする。
参考: [俳優の「プロフィール資料」何が必要？（俳優の下積み生活）](https://manami-hayashi.com/blog/actor-portfolio/)

### 2.1 サンプルから抽出したレイアウト構成

```
┌─────────────────────────────────────┐
│  氏名（大・明朝系） ローマ字表記                      │ ← ヘッダー
│  ──────────────────────────────     │
│  生年月日（年齢自動計算）（性別）                     │
│  身長・体重                                          │ ← 基本情報ブロック
│  B/W/H・足サイズ・頭囲・服サイズ                      │   （中央揃え・複数行）
│  趣味・特技（カンマ区切りリスト）                      │
│                                                     │
│  ┌──────────┐   ┌──────────┐                       │
│  │ バストアップ │   │  全身写真  │                    │ ← 写真ブロック×2
│  └──────────┘   └──────────┘                       │
│                                                     │
│ 【最新の活動状況】                                    │
│ 【映画】               【TV】                        │
│  ・強調行(赤字太字)      ・年 局『作品名』話数 役名     │ ← 経歴ブロック
│  ・年『作品名』監督 役名  【CM】                       │   （2カラム・
│  ・…                   ・…                          │    カテゴリ別リスト）
│                        【MV】                        │
│ 【自己紹介】            ・…                          │
│  自由文テキスト         ┌────────────────┐           │
│                        │【動画資料】URLリンク │        │ ← リンク枠
│                        └────────────────┘           │
│  ─────────────────────────────────                  │
│  [ロゴ] 会社名  ☎電話   住所 / ✉メール / 🌐URL        │ ← フッター(共通)
└─────────────────────────────────────┘
```

### 2.2 記載項目（データ項目）

- **ヘッダー**: 芸名（漢字）、ふりがな（任意）、ローマ字
- **基本情報**: 生年月日→年齢自動計算（表示/非表示可）、性別、身長、体重、B/W/H、足サイズ、頭囲、服サイズ（例: L/XL）、血液型（任意）、出身地（任意）
- **趣味・特技**: 複数項目（カンマ区切り表示）
- **写真**: バストアップ＋全身の 2 枚が基本。差し替え候補を複数登録し選択
- **経歴（最新の活動状況）**: カテゴリ（映画/TV/CM/MV/舞台/その他）別の明細リスト
  - 明細行: 年、作品名、話数・部門、役名、監督/局名、補足（映画祭入選等）
  - **強調表示フラグ**（サンプルの赤字太字のように最新作・主要作を目立たせる）
- **自己紹介**: 自由文（改行可）
- **動画資料**: ラベル＋URL の複数リンク（PDF 上でクリック可能なリンクとして出力）
- **事務所要素（全タレント共通）**: ロゴ画像、会社名、電話、住所、メール、Web サイト URL、サイン（署名画像）、SNS/QR コード（任意）

### 2.3 形式

- A4 縦・1 枚（情報量に応じて 2 枚まで対応）
- PDF 出力（リンク埋め込み・日本語フォント埋め込み）。印刷にも耐える解像度
- 明朝系（氏名）＋ゴシック系（本文）の混植など、フォント指定が可能であること

## 3. 機能要件

優先度: **[M] MVP 必須 / [S] 第2フェーズ / [C] 将来検討**

### F1. タレント情報管理
- [M] タレントの登録・編集・削除（論理削除）・一覧・検索（名前・ふりがな・タグ）
- [M] §2.2 の全項目を構造化フィールドで保持。経歴はカテゴリ別の明細行（並べ替え可・強調フラグ付き）
- [M] 年齢は生年月日から自動計算（出力時に表示/非表示を選択可）
- [M] 500 名規模でも一覧・検索が快適に動作（顔写真サムネイル付きグリッド/リスト表示）
- [S] タグ・カテゴリ管理（俳優/モデル/声優、性別、年代等）による絞り込み
- [S] CSV / Excel からの一括インポート（既存名簿の移行用）
- [C] タレント本人による下書き入力 → 事務所承認フロー

### F2. 写真管理
- [M] タレントごとに複数写真を登録（JPEG/PNG/HEIC、ドラッグ&ドロップ対応）
- [M] 写真に用途タグ（バストアップ/全身/スナップ）を付与し、テンプレートの写真枠へ選択配置
- [M] 写真枠内でのトリミング・位置調整（枠に自動フィット＋手動微調整）
- [M] 写真はローカルのデータフォルダに保存し、サムネイルを自動生成（500 名×多数枚でも一覧が軽快）
- [S] 撮影日管理・古い写真の入替アラート
- [C] 背景切り抜き・明るさ自動補正

### F3. レイアウトエディタ（本ツールの中核）
- [M] **ブラウザ上の WYSIWYG エディタで、要素を自由にドラッグ移動・リサイズできる**
  - 要素の種類: テキスト（データ項目バインド／固定文言）、写真枠、経歴リスト枠（カテゴリ指定）、画像（ロゴ・サイン）、リンク枠、罫線・図形、フッター
  - スナップガイド・グリッド・整列（左揃え/中央/等間隔）・重なり順(z-order)
  - フォント・サイズ・太字・色・行間・揃えの指定（強調行のスタイル指定を含む）
  - A4 縦キャンバス上で実寸プレビューしながら編集（ズーム可）
- [M] レイアウトは**テンプレート**として保存し、全タレントに適用（データとレイアウトの分離）
- [M] テンプレート修正（ロゴ変更・枠移動等）は、全タレントの次回出力に即時反映
- [S] テンプレート複数管理（オーディション用/営業用等）・複製・項目の表示/非表示切替
- [S] タレント個別のレイアウト微調整（テンプレートからのオーバーライド。経歴が多い人だけ枠を広げる等）
- [S] リストのあふれ制御（枠に入り切らない場合の警告／自動フォントサイズ縮小／2 ページ目送り）
- [C] 複数ページテンプレート・ページマスター

### F4. ブランド管理（事務所共通アセット）
- [M] ロゴ画像、サイン（署名）画像、会社名・電話・住所・メール・URL、ブランドカラー、使用フォントを一元登録
- [M] テンプレートのフッター等に自動配置され、変更は 1 箇所の修正で全タレントに反映

### F5. 出力・共有
- [M] PDF 出力（A4・300dpi 相当、フォント埋め込み、動画資料 URL はクリック可能リンク）
- [M] 出力前プレビュー（エディタと同一描画で見た目が一致）
- [M] 一括出力（一覧で複数タレントを選択 → 各 1 PDF をフォルダへ書き出し）
- [S] 画像（PNG/JPEG）出力、PowerPoint（.pptx）出力（既存業務フローとの互換用）
- [C] 共有用の静的 HTML 書き出し（事務所サイト掲載用）

### F6. データ保全・版管理（ローカル運用の要）
- [M] データは**ローカルのデータフォルダ 1 箇所**（DB ファイル＋写真フォルダ）に集約し、フォルダコピーだけでバックアップ・PC 移行が完結する構造
- [M] ワンクリックバックアップ（ZIP 書き出し）と復元
- [M] 更新履歴の記録（いつ・どのタレントの何を変更したか）
- [S] 自動バックアップ（起動時/終了時に世代保存）、出力履歴と旧版 PDF の保管
- [S] 更新リマインド（例: 経歴が 6 か月更新されていない）

### F7. アクセス管理
- [M] ローカル利用のため必須認証は設けないが、**外部からのアクセスを遮断**（localhost のみで待ち受け）
- [S] 起動時パスコード（共用 PC 対策）、操作ユーザー名の記録
- [C] LAN 内の複数 PC からの同時利用（サーバーモード＋ロール管理）

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 動作環境 | Windows 10/11・macOS。UI は Chrome / Edge 最新版。オフラインで全機能が動作（インターネット接続不要） |
| 性能 | タレント 500 名・写真 1 万枚規模で、一覧表示・検索 1 秒以内、エディタ操作 60fps 目安、PDF 1 件 10 秒以内・一括 100 件 15 分以内 |
| データ保護 | 個人情報・肖像をローカル保持するため、待ち受けは localhost 限定。データフォルダの場所を明示し、事務所の PC 運用ルール（ディスク暗号化・バックアップ）で保護。タレント削除時は写真含め完全削除可能 |
| 信頼性 | 編集内容の自動保存。DB は単一ファイル（破損対策に世代バックアップ） |
| 操作性 | IT に詳しくない担当者が研修なしで使える日本語 UI。エディタは PowerPoint 操作感に寄せる（ドラッグ・整列・書式） |
| 保守性 | データ（DB）とレイアウト（テンプレート JSON）を分離。項目追加・テンプレート追加が容易な構造 |
| 導入容易性 | インストーラまたは実行ファイル一つで起動 → ブラウザが自動で開く。技術者不在でも導入可能 |
| コスト | ランニングコストは原則ゼロ（ローカル完結・サーバー費用なし） |

## 5. アーキテクチャ（案）

### 5.1 方式比較（「ブラウザ UI ＋ ローカル保存」の実現方法）

| 方式 | 概要 | 評価 |
|---|---|---|
| **A. ローカルアプリ（デスクトップアプリ内蔵サーバー）** | Tauri または Electron でパッケージし、内部でローカルサーバー＋SQLite を起動。UI は内蔵 WebView またはブラウザ | **◎ 推奨**。ダブルクリックで起動、データフォルダ管理・ファイル出力が自由、配布が容易 |
| B. ローカル Node サーバー＋ブラウザ | `npm start` 等でローカルサーバーを立て、ブラウザで `localhost` を開く | ○ 開発は最速。ただし起動手順に技術的ハードルが残る（開発初期はこの形で進め、後に A にパッケージ） |
| C. ブラウザ完結（PWA + OPFS/File System Access API） | サーバーなし。ブラウザ内ストレージに保存 | △ 導入は最も簡単だが、1 万枚規模の写真管理・一括 PDF 出力・バックアップ運用に制約が多い |

**結論**: 開発中は B、配布時に A（Tauri 推奨: 軽量・実行ファイルが小さい）へパッケージする 2 段構え。

### 5.2 構成図

```
┌─ ローカル PC ─────────────────────────────────────┐
│                                                    │
│  ブラウザ (Chrome/Edge)                             │
│   ├ タレント管理画面 (React SPA)                     │
│   ├ レイアウトエディタ (キャンバス編集・実寸表示)       │
│   └ プレビュー (エディタと同一のHTML/CSS描画)         │
│              │ HTTP (localhost のみ)                │
│  ローカルアプリ (Tauri/Node)                         │
│   ├ API サーバー (Fastify)                          │
│   ├ PDF 生成 (Chromium ヘッドレス印刷)               │
│   └ サムネイル生成 (sharp)                          │
│              │                                     │
│  データフォルダ（場所は設定で変更可）                  │
│   ├ profile.db        … SQLite（全テキストデータ）   │
│   ├ photos/<talent>/  … 写真原本                    │
│   ├ thumbs/           … サムネイルキャッシュ          │
│   ├ assets/           … ロゴ・サイン・フォント        │
│   ├ templates/        … レイアウト定義 JSON          │
│   └ backups/          … 世代バックアップ(ZIP)        │
└────────────────────────────────────────────────────┘
```

- **エディタ・プレビュー・PDF が同一の HTML/CSS 描画**を共有することで「見たまま出力」（WYSIWYG）を保証
- データフォルダを丸ごとコピーすればバックアップ・PC 移行が完了する

### 5.3 技術スタック（推奨）

| レイヤ | 推奨 | 理由 |
|---|---|---|
| UI | React + TypeScript + Vite | エディタのような対話的 UI に実績豊富 |
| レイアウトエディタ | 自作キャンバス（DOM/CSS transform ベース）＋ dnd 系ライブラリ | PDF 描画と同一の DOM を編集対象にでき、WYSIWYG を担保 |
| API / アプリ | Fastify (Node.js) → Tauri でパッケージ | 軽量・配布容易 |
| DB | SQLite（better-sqlite3） | 単一ファイル・500 名規模に十分・バックアップ容易 |
| 画像処理 | sharp | サムネイル生成・HEIC 変換 |
| PDF 生成 | ヘッドレス Chromium 印刷（Playwright または Tauri 内蔵 WebView 印刷） | HTML/CSS テンプレートをそのまま PDF 化。リンク・日本語フォント埋め込み対応 |
| .pptx 出力（S） | pptxgenjs | 既存 PowerPoint フローとの互換 |

## 7. 画面構成（案）

1. **タレント一覧**: 顔写真グリッド、検索・タグ絞り込み、複数選択 →「PDF 一括出力」
2. **タレント編集**: 基本情報フォーム／写真管理（D&D・用途タグ・トリミング）／経歴（カテゴリ別明細・並べ替え・強調フラグ）／動画リンク／自己紹介
3. **レイアウトエディタ**: A4 キャンバス、要素パレット（テキスト/写真枠/経歴リスト/画像/リンク/罫線）、プロパティパネル（バインド項目・書式）、サンプルタレントでの実データプレビュー切替
4. **プレビュー & 出力**: タレント × テンプレートを選択 → 実寸プレビュー → PDF 保存
5. **設定**: 事務所情報・ロゴ・サイン／フォント／データフォルダの場所／バックアップ・復元

ユーザーフロー（更新業務）: 一覧で検索 → 編集 → 保存 → プレビュー → PDF 出力（目標 5 分以内）
