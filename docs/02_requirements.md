# 需要分析・システム要件定義書

タレントプロフィール作成・メンテナンスツール
作成日: 2026-07-30 ／ 版: v0.1（初版ドラフト）

---

## 1. 背景と需要分析

### 1.1 現状の課題（As-Is）

タレント事務所では、所属タレントの宣材プロフィールを Word / PowerPoint で 1 人ずつ手作業で作成している。

| # | 課題 | 影響 |
|---|---|---|
| C1 | 新規作成に時間がかかる（レイアウト調整・写真配置・体裁合わせ） | 1 人あたり数時間の作業。タレント増員時にスケールしない |
| C2 | 写真差し替え・サイズや経歴の更新のたびにレイアウトが崩れる | 更新が後回しになり、古い情報のまま送付されるリスク |
| C3 | 事務所ロゴ・サイン・連絡先などの共通要素がファイルごとにバラバラ | ブランドの統一感がない。連絡先変更時に全ファイル修正が必要 |
| C4 | ファイルが個人 PC・メール添付で分散し、どれが最新版か分からない | 版管理ミス、誤送付、担当者不在時に更新できない属人化 |
| C5 | 用途別（オーディション用／営業用／Web 用）に別ファイルを複製している | 複製の数だけ更新漏れが発生 |

### 1.2 想定ユーザーと需要

| ユーザー | 人数想定 | 主なニーズ |
|---|---|---|
| マネージャー・デスク担当（主ユーザー） | 数名 | プロフィールの新規作成・更新・出力を短時間で行いたい |
| 事務所代表・管理者 | 1〜2名 | ブランド統一、全タレントの情報の一覧性、権限管理 |
| タレント本人（将来拡張） | 〜数十名 | 自分の情報（特技・経歴等）の下書き提出 |
| 資料の受け手（キャスティング・クライアント） | 外部 | 見やすい PDF／最新情報の Web 閲覧（閲覧のみ） |

**期待効果（需要の定量イメージ）**: タレント 30 名 × 年 4 回更新 × 1 回 2 時間（手作業）＝ 年 240 時間 → フォーム入力 15 分に短縮できれば **年 200 時間以上の削減**。加えて誤送付・ブランド不統一という品質リスクの解消。

### 1.3 ゴール（To-Be）

> タレント情報を一元管理し、**「入力・写真アップロード → テンプレート選択 → PDF 出力」の 3 ステップ**で、事務所ブランドの統一されたプロフィールがいつでも最新の状態で出力できる。

## 2. プロフィール資料の要件（出力物の仕様）

参考: [俳優の「プロフィール資料」何が必要？（俳優の下積み生活）](https://manami-hayashi.com/blog/actor-portfolio/) ほか業界慣行

- **判型**: A4 縦、1〜2 ページ（1 枚目: 写真＋基本情報、2 枚目: 経歴詳細）
- **記載項目**:
  - 写真: バストアップ（メイン）、全身、スナップ（複数登録し用途で選択）
  - 基本情報: 芸名（ふりがな・ローマ字）、生年月日／年齢（表示・非表示切替可）、出身地、身長・体重・B/W/H・靴サイズ、血液型（任意）
  - 経歴: 出演歴（映画/ドラマ/CM/舞台/MV/雑誌等のカテゴリ別・年度順）、受賞歴
  - スキル: 特技、資格、方言、語学、趣味、自己PR
  - 事務所要素: ロゴ、事務所名・連絡先、担当者名、サイン（署名画像）、SNS/プロフィールページ QR コード
- **デザイン原則**: 読み手（キャスティング担当）が数秒で判断できること。写真が主役、文字は整理されて簡潔に

## 3. 機能要件

優先度: **[M] MVP 必須 / [S] 第2フェーズ / [C] 将来検討**

### F1. タレント情報管理
- [M] タレントの登録・編集・削除（論理削除）・一覧・検索（名前・タグ・所属状態）
- [M] 項目: §2 の記載項目すべてを構造化フィールドで保持（経歴は「年／カテゴリ／作品名／役名等」の明細行）
- [M] 年齢は生年月日から自動計算（出力時に表示/非表示を選択可）
- [S] タグ・カテゴリ管理（俳優/モデル/声優、性別、年代等）による絞り込み
- [C] タレント本人による下書き入力 → 事務所承認フロー

### F2. 写真管理
- [M] タレントごとに複数写真をアップロード（JPEG/PNG/HEIC、1 枚 20MB 程度まで）
- [M] 写真に用途タグ（バストアップ/全身/スナップ）と「メイン」指定を付与
- [M] 差し替えは選択操作のみ。テンプレート側の枠に自動フィット（トリミング枠の位置調整 UI 付き）
- [S] 撮影日管理・古い写真の入替アラート（例: 撮影から 1 年経過で通知）
- [C] 背景切り抜き・明るさ自動補正

### F3. テンプレート・ブランド管理
- [M] 事務所共通アセットの登録: ロゴ画像、サイン（署名）画像、事務所名・連絡先、ブランドカラー、フォント
- [M] プロフィールテンプレート（A4 縦 1〜2 ページ）を最低 2 種（オーディション用/営業用）用意し、共通アセットを自動配置
- [M] テンプレート修正（ロゴ変更・連絡先変更等）は全タレントの出力に即時反映
- [S] テンプレートの複数管理・項目の表示/非表示切替（例: 営業用はB/W/H非表示）
- [C] レイアウトエディタ（管理者が枠位置をドラッグで調整）

### F4. 出力・共有
- [M] PDF 出力（印刷品質 300dpi 相当、フォント埋め込み）
- [M] 出力前プレビュー（ブラウザ上で実物と同じ見た目を確認）
- [S] 画像（PNG/JPEG）出力、PowerPoint（.pptx）出力（既存業務フローとの互換用）
- [S] 一括出力(複数タレントをまとめて PDF 化・ZIP ダウンロード)
- [C] 共有用 URL 発行（有効期限付き・閲覧のみの Web プロフィールページ）

### F5. 更新・版管理
- [M] 更新履歴の記録（誰が・いつ・何を変更したか）
- [S] 出力履歴（いつ・どのテンプレで出力したか）と旧版 PDF の保管
- [S] 更新が必要な項目のリマインド（例: 経歴が 6 か月更新されていない）

### F6. ユーザー・権限管理
- [M] ログイン認証（メール＋パスワード、最小構成で可）
- [S] ロール: 管理者（テンプレ・アセット・ユーザー管理）／編集者（タレント情報編集・出力）／閲覧者
- [C] タレント本人ロール（自分の情報のみ下書き編集可）

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | タレントの個人情報（生年月日・サイズ等）と肖像（写真）を扱うため、通信は HTTPS 必須、写真ストレージは非公開（署名付き URL でのみ配信）、認証必須。共有 URL は有効期限・無効化可能 |
| 個人情報保護 | 個人情報保護法対応: アクセスできる者の限定（権限管理）、削除要求への対応（タレント削除時に写真含め完全削除できること） |
| 性能 | タレント 100 名・写真 2,000 枚規模で一覧・検索 1 秒以内、PDF 生成 10 秒以内 |
| 可用性 | 業務時間内の利用が主。SLA は不要だが日次バックアップ（DB・写真）必須 |
| 操作性 | PC ブラウザ（Chrome/Edge/Safari 最新）対応。IT に詳しくない担当者が研修なしで使える UI。日本語 UI |
| 保守性 | テンプレート追加・項目追加が開発者作業で容易に行える構造（データとテンプレートの分離） |
| コスト | 小規模事務所で維持できる月額数千円以内のインフラ費を目安 |

## 5. データモデル（案）

```
Agency（事務所）
 ├─ id, name, contact(tel/email/address), logo_image, sign_image,
 │   brand_color, default_font
 │
Talent（タレント）
 ├─ id, agency_id, stage_name, kana, romaji, birthdate, birthplace,
 │   height, weight, bust, waist, hip, shoe_size, blood_type,
 │   pr_text, status(所属/準所属/退所), tags[], created_at, updated_at
 │
 ├─ Photo（写真）        : id, talent_id, file, role(bust_up/full_body/snap),
 │                         is_main, shot_date, crop(x,y,w,h)
 ├─ Career（経歴明細）   : id, talent_id, year, category(映画/ドラマ/CM/舞台/…),
 │                         title, role_name, note, sort_order
 └─ Skill（特技等）      : id, talent_id, type(特技/資格/語学/方言/趣味), label, level
 │
Template（テンプレート）
 ├─ id, agency_id, name, purpose(オーディション/営業/Web), pages,
 │   layout_def(JSON), visible_fields(JSON)
 │
AuditLog（更新履歴） / ExportLog（出力履歴）
User（ユーザー） : id, email, name, role(admin/editor/viewer)
```

## 6. 画面構成（案）

1. **ログイン**
2. **タレント一覧**（顔写真グリッド表示、検索・タグ絞り込み、「PDF一括出力」）
3. **タレント編集**（基本情報フォーム／写真管理タブ／経歴タブ ※明細行の追加・並べ替え／特技タブ）
4. **プレビュー & 出力**（テンプレート選択 → A4 プレビュー → PDF ダウンロード）
5. **設定**（事務所情報・ロゴ・サイン・ブランドカラー／テンプレート管理／ユーザー管理）

ユーザーフロー（更新業務）: 一覧でタレント検索 → 編集 → 保存 → プレビュー → PDF 出力（目標 5 分以内）

## 7. 技術スタック（推奨案）

| レイヤ | 推奨 | 理由 |
|---|---|---|
| フロントエンド | Next.js（React）+ TypeScript | フォーム中心の管理画面と HTML/CSS ベースの帳票プレビューを 1 技術で実現 |
| バックエンド | Next.js API Routes（小規模なら一体型） | 構成を最小化し保守コストを下げる |
| DB | PostgreSQL（Supabase 等のマネージド） | リレーショナルな明細データ（経歴等）に適合。認証・ストレージも同梱可能 |
| 写真ストレージ | S3 互換オブジェクトストレージ（非公開バケット＋署名付きURL） | 肖像保護と低コスト |
| PDF 生成 | HTML/CSS テンプレート → Playwright(Chromium) で印刷 PDF 化 | テンプレートを Web 標準技術で記述でき、プレビュー＝出力の見た目一致（WYSIWYG）を保証。日本語フォント埋め込み可 |
| .pptx 出力（S） | python-pptx または officegen 系ライブラリ | 既存 PowerPoint フローとの互換 |
| ホスティング | Vercel + Supabase（または国内 VPS 1 台） | 月額数千円以内で運用可能 |

> 代替案: 開発を最小化するなら「Notion/スプレッドシート（データ管理）＋ Canva 一括作成」の暫定運用も可能だが、§01_research の通り一括反映・版管理が実現できないため、恒久策としては非推奨。

## 8. 開発ロードマップ（案）

| フェーズ | 内容 | 目安工数 |
|---|---|---|
| Phase 0（完了） | 調査・要件定義（本ドキュメント） | — |
| Phase 1: MVP | タレント CRUD／写真アップロード＆差し替え／固定テンプレート 1 種／ロゴ・サイン・連絡先の共通アセット反映／PDF 出力／簡易ログイン | 4〜6 週間 |
| Phase 2 | テンプレート複数化・項目表示切替／一括出力／pptx・画像出力／権限ロール／更新・出力履歴／リマインド | 4〜6 週間 |
| Phase 3 | 共有 URL（Web プロフィール）／タレント本人入力＋承認フロー／写真加工補助 | 適宜 |

### MVP の受け入れ基準（Doneの定義）

- [ ] 新規タレントを登録し、写真 3 枚を割り当て、A4・2 ページの PDF を 15 分以内に出力できる
- [ ] 写真差し替え・経歴追記をしてもレイアウトが崩れない
- [ ] 設定画面でロゴ／連絡先を変更すると、全タレントの次回出力に反映される
- [ ] 認証なしではいかなるデータ・写真にもアクセスできない

## 9. 未確定事項（ヒアリングが必要な項目）

1. 所属タレント数と担当者数（規模により Phase 1 の構成を調整）
2. 現行の Word/PowerPoint プロフィールのサンプル（テンプレートの再現元として必須）
3. 用途別フォーマットの種類（オーディション用／営業用／Web 用の違い）
4. 「サイン」の具体像（署名画像か、承認印か、デザイン要素か）
5. タレント本人にどこまで入力させたいか（Phase 3 の要否）
6. 印刷会社入稿の有無（トンボ・CMYK 対応が必要かどうか）
