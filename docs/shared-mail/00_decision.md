# 共有メール管理システム 自作可否の判断

> 複数のメールアドレスを、複数人が1つの管理画面で扱いたい（サイボウズ「メールワイズ」相当）。自作は可能か。
>
> 読み手: 開発者本人 / 作成日: 2026-08-17 / ステータス: 判断待ち

---

## 1. 結論

**技術的には自作可能。ただし今回の規模（〜5人・〜3アドレス）では、費用面で自作がSaaSを上回ることはない。**

判断軸は「安く済むか」ではなく「**この仕組みを自分で持つことに、年3.6万円以上の価値があるか**」に尽きる。

| 問い | 答え |
|---|---|
| 作れるか | 作れる。難所は4つに限定でき、いずれも既知の解法がある（→ §4） |
| どのくらいかかるか | PoC 2〜3人日 / MVP 10〜15人日 / 実運用 +10〜20人日。合計 **1〜1.5人月** |
| 安くなるか | ならない。メールワイズは **約36,000円/年**（5人）。自作の初期工数を人件費換算すると初年度で数十倍 |
| それでも作る理由があるか | §3 のチェックリストで判定する |

---

## 2. 費用の実額（〜5人・3アドレス／年額）

| 選択肢 | 初期費用 | ランニング | 備考 |
|---|---|---|---|
| **メールワイズ スタンダード** | 0円 | **約36,000円/年** | 600円/人・月 × 5人。最低5ユーザー契約。1アプリにつき10アドレスまで |
| メールワイズ プレミアム | 0円 | 約108,000円/年 | 1,800円/人・月。集計・分析機能つき |
| yaritori | 0円 | 約119,000円/年 | 1,980円/人・月、最低2ユーザー |
| Re:lation | 0円 | 0円〜 | フリープランは1ユーザー・受信箱1つ・100MBのため、今回の要件（3アドレス・5人）は満たさない |
| **OSS（FreeScout）セルフホスト** | 0円 | 約12,000〜24,000円/年 | VPS代のみ。PHP/Laravel。日本語UIあり |
| **フルスクラッチ自作** | **開発 1〜1.5人月** | 約24,000〜36,000円/年 | VPS + DB + AI API 従量 |

要するに、**メールワイズ3年分（約11万円）が、自作の初期工数と釣り合うかどうか**という話になる。釣り合わない。

---

## 3. それでも自作を選ぶ条件（チェックリスト）

以下に**1つも当てはまらないなら、メールワイズ導入を推奨する**。

- [ ] AIによる自動下書き・要約・分類・優先度判定を、**自社仕様で自由に**組み込みたい（SaaSのAI機能は仕様が固定され、プロンプトも触れない）
- [ ] 人数課金を避けたい。将来の増員でも費用を一定に保ちたい
- [ ] 顧客のメール本文を外部SaaSに預けたくない（情報管理方針）
- [ ] **同種の仕組みを他社にも提供する構想がある**（自社プロダクト化・受託の型づくり）
- [ ] メール処理基盤の内製ノウハウ自体を資産にしたい

### 今回の前提で外れた条件

当初「既存のタレント実績管理ツールとメール履歴を統合できる」ことが自作の最大の動機になり得たが、ヒアリングの結果 **統合は不要（完全に別システムで良い）** と確定した。この理由は使えない。

結果として、残る動機は実質 **「AI活用の自由度」と「プロダクト化・ノウハウ蓄積」** の2つに絞られる。この2つが本気の目的でないなら、自作する経済的な理由はない。

---

## 4. 自作した場合の難所は4つだけ

「メールを取ってきて画面に出す」こと自体は難しくない。詰まるのは以下に集約される。詳細は [01_architecture.md](01_architecture.md)。

| # | 難所 | 要点 |
|---|---|---|
| 1 | **Gmail API の審査要件** | メール読み取りは restricted scope。外部公開アプリだと CASA という年次のセキュリティ審査が必要。ただし **Google Workspace 組織内限定(Internal)アプリなら審査免除**。自社利用ならここは回避できる |
| 2 | **日本語メールの文字化け** | ISO-2022-JP は状態を持つ符号化方式で、Node の定番 `iconv-lite` が非対応。件名（MIMEエンコード語）と本文の両方で踏む |
| 3 | **IMAP差分取得の取りこぼし・重複** | UIDVALIDITY / UID の管理を誤ると、メールが消える or 二重取り込みされる |
| 4 | **二重対応の防止** | 「誰かが今返信を書いている」を複数人に正しく見せる排他制御。これが無いと共有メールを使う意味がない |

---

## 5. 中間解: OSS セルフホスト

「自作 vs SaaS」の二択にしないこと。第3の選択肢として **FreeScout**（PHP/Laravel、共有受信箱型、日本語UIあり）がある。

| | フルスクラッチ | FreeScout | メールワイズ |
|---|---|---|---|
| 到達までの時間 | 1〜1.5人月 | 数日 | 即日 |
| 年間費用 | VPS代＋工数 | VPS代のみ | 約36,000円 |
| 日本語UI | 自分で作る | あり | ネイティブ |
| 仕様の自由度 | **完全** | 中（プラグイン範囲） | 低 |
| AI連携の自由度 | **完全** | 低 | 低（固定機能） |
| 保守責任 | 全部自分 | 全部自分 | ベンダー |

**AI活用が目的なら FreeScout は中途半端**になりやすい。目的が「単に共有受信箱が欲しい」ならメールワイズが最短、「作ることに価値がある」ならフルスクラッチ。FreeScout が最適なのは「SaaSに費用を払いたくないが、作る時間もない」場合に限られる。

---

## 6. 推奨する進め方

いきなり全体を作らない。**PoC を 2〜3人日で作り、上記の難所2（文字化け）と難所3（取り込みの安定性）を実データで確認する**。

```
PoC（2〜3人日）
  IMAP 1アドレス / 受信一覧 / 担当者割当 / ステータス / 返信
        │
        ├─ 実際の業務メールを流し込んで検証
        │    ・日本語メールが文字化けしないか
        │    ・数日回して取りこぼし・重複が出ないか
        │
   ┌────┴────┐
   │         │
 通過      詰まる
   │         │
 MVPへ    メールワイズ導入に切替（PoCの2〜3人日は判断コストとして許容）
```

この形なら、**最大でも3人日で「自作すべきか」の答えが出る**。全体設計と工数の内訳は [02_roadmap.md](02_roadmap.md) を参照。
